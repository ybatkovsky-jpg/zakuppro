# M005-S04-T01: Create User model, RBAC types, and database migration

## Why
RBAC requires a User model to store credentials and roles. Projects need ownership tracking. A database migration adds the new tables and columns.

## Do
1. Add User model to backend/models.py:
   - Fields: id, username, email, hashed_password, role (enum: owner/manager/warehouse)
   - Add owner_id foreign key to Project model
   - Create Role enum (str enum: OWNER, MANAGER, WAREHOUSE)
2. Create Alembic migration backend/alembic/versions/xxx_add_rbac_models.py:
   - Create users table with role column
   - Add owner_id column to projects table (nullable for existing data)
   - Backfill existing projects with owner_id=1 (default owner)
3. Update backend/schemas.py with auth schemas:
   - UserCreate, UserResponse (exclude password)
   - LoginRequest (username, password), LoginResponse (access_token, token_type, role)
4. Create seed data script for initial owner user

## Done when
- Migration file exists with users table and owner_id column
- User model and Role enum are defined in models.py
- Auth schemas exist in schemas.py

## Inputs

- `backend/models.py`
- `backend/schemas.py`
- `backend/database.py`

## Expected Output

- `backend/models.py`
- `backend/schemas.py`
- `backend/alembic/versions/xxx_add_rbac_models.py`
- `backend/scripts/seed_owner.py`
