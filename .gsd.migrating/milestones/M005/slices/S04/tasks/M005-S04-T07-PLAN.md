# M005-S04-T07: Frontend auth types and login API proxy

## Why
Frontend needs TypeScript types for auth and a way to call the login endpoint. The API proxy pattern follows S01 conventions.

## Do
1. Update src/types/fastapi.ts:
   - Add LoginRequest { username: string; password: string }
   - Add LoginResponse { access_token: string; token_type: string; role: string }
   - Add User { id: number; username: string; role: string }
   - Add UserRole type: 'owner' | 'manager' | 'warehouse'
2. Create src/app/api/auth/login/route.ts:
   - POST handler that proxies to FastAPI /api/auth/login
   - Transform error responses per S01 pattern
3. Update src/lib/api-client.ts:
   - Add getAuthToken() helper to read JWT from localStorage
   - Add setAuthToken(token) helper to store JWT
   - Modify apiFetch to include Authorization header from localStorage
4. Create src/lib/auth.ts with:
   - login(username, password) function
   - isAuthenticated() check
   - getUserRole() helper

## Done when
- Frontend can call /api/auth/login and receive JWT
- Token is stored in localStorage
- API client includes Authorization header in requests

## Inputs

- `src/types/fastapi.ts`
- `src/lib/api-client.ts`

## Expected Output

- `src/types/fastapi.ts`
- `src/app/api/auth/login/route.ts`
- `src/lib/api-client.ts`
- `src/lib/auth.ts`

grep -q 'LoginRequest' src/types/fastapi.ts && grep -q 'LoginResponse' src/types/fastapi.ts && test -f src/app/api/auth/login/route.ts && test -f src/lib/auth.ts

Auth token storage is visible in localStorage for debugging. API errors include 403 status for authorization failures.
