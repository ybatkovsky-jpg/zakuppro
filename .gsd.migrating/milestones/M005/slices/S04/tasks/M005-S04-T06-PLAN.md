# M005-S04-T06: Update remaining routers with RBAC (stock_items, suppliers, analytics)

## Why
All API endpoints need RBAC to complete the security model. Stock items for warehouse, suppliers and analytics for owner/managers.

## Do
1. Update backend/routers/stock_items.py:
   - Allow all roles for GET (warehouse needs access)
   - POST/PUT/DELETE: require_role(['owner', 'manager'])
   - No ownership filtering (stock is shared)
2. Update backend/routers/suppliers.py:
   - GET: allow all roles for read
   - POST/PUT/DELETE: require_role(['owner'])
   - Manager: read-only access
   - Warehouse: 403 for all supplier endpoints
3. Update backend/routers/analytics.py:
   - GET /api/analytics/dashboard:
     - Owner: all data
     - Manager: only their projects' metrics
     - Warehouse: 403
   - Add ownership filtering to dashboard queries
4. Verify each router returns appropriate 403 for unauthorized roles

## Done when
- Stock items endpoint accessible to warehouse role
- Suppliers endpoint is read-only for managers, full for owners, 403 for warehouse
- Analytics filters by ownership for managers
- All routers require valid JWT token

## Inputs

- `backend/auth.py`
- `backend/rbac.py`
- `backend/routers/stock_items.py`
- `backend/routers/suppliers.py`
- `backend/routers/analytics.py`

## Expected Output

- `backend/routers/stock_items.py`
- `backend/routers/suppliers.py`
- `backend/routers/analytics.py`

## Verification

grep -q 'current_user' backend/routers/stock_items.py && grep -q 'current_user' backend/routers/suppliers.py && grep -q 'current_user' backend/routers/analytics.py

## Observability Impact

Each router logs role-based access denials with endpoint and required permission
